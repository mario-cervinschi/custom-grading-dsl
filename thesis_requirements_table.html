FR-01 The system shall evaluate grading rules in a fully deterministic manner, producing identical outputs for identical inputs with no side effects or hidden state. ANTLR4 Grammar & Interpreter High
FR-02 The system shall abstract all parsing and validation complexity behind a clean API, exposing only structured results to consuming layers. Go Backend / Language Server High
FR-03 The system shall perform real-time AST validation without blocking the UI thread, maintaining editor responsiveness at all times. Frontend Language Server (Tree-sitter) High
FR-04 Autocompletion, grading evaluation, and the Language Server Protocol layer shall operate as independent modules with no shared mutable state. LSP WebSocket Proxy & Angular Services High
FR-05 The system shall provide a sandboxed preview mode allowing teachers to test grading formulas against sample data before publishing them. Preview Panel (Angular) & Go Evaluator High
FR-06 The editor shall suppress backend evaluation requests when the current DSL source contains syntax errors, preventing invalid execution payloads. Monaco Editor & RxJS Pipeline High
FR-07 The system shall surface syntax and semantic errors as inline diagnostics (squiggly underlines) within the editor, with descriptive hover messages. Monaco Editor / Tree-sitter Validator Medium
FR-08 The autocompletion engine shall provide context-aware suggestions that adapt to the current cursor position and grammatical context within the DSL. Tree-sitter Completion Provider Medium
FR-09 The system shall communicate between the frontend and backend Language Server exclusively via a WebSocket transport, keeping protocol and transport layers decoupled. LSP-over-WebSocket Proxy (Go) Medium
FR-10 The grading DSL shall support conditional branching, direct score assignment, and weighted formula expressions as first-class language constructs. ANTLR4 Grammar (ExprParser / ExprLexer) Low
